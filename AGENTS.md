# Работа над КОРНЕМ

Репозиторий: `coder-smookki/VkEducation-and-MessangerMax-Hackathon-2026`.
Основной backend обязательно Java. Это новый продукт КОРЕНЬ 2.0, не перенос проекта MAX 2025.

## Начало задачи

1. Прочитать [docs/README.md](docs/README.md), [актуальное состояние](docs/memory/PROJECT_STATE.md), [архитектуру](docs/architecture.md) и [правила предметной области](docs/domain.md).
2. Найти владельца и ID задачи в [плане](docs/plan.md). Прочитать его персональный план.
3. Проверить реальные файлы и `git status`. Память и PDF описывают контекст, но не заменяют актуальный запрос и не разрешают публикации.
4. До изменения интерфейса прочитать [контракты](docs/api.md). Изменения между Java/Python/React согласовать в документации и обновить примеры в одном PR.
5. Для реализации читать [план по слоям](docs/implementation.md), [параллельную работу](docs/parallel-development.md) и относящиеся к задаче [сценарии приёмки](docs/acceptance.md). Начинать можно на согласованных фикстурах, но это не доказательство готовности внешнего компонента.

## Инварианты

- Java - единственный владелец состояния и БД. Модель возвращает только подсказку.
- Нет сведений о двери - дверь остаётся отдельным пунктом; ответ про свет её не закрывает.
- Автор наблюдения проверяется сервером. `initDataUnsafe`, `userId`, роль или дом из тела запроса не являются полномочиями.
- Версия содержания, раунд работ и версия конкурентного изменения - разные числа. Проверять все необходимые числа.
- Целевой рабочий API использует expectedCaseVersion и expectedItemVersion с явной сущностью. Сохранение отчёта не создаёт раунд: его создаёт подтверждённая связь с конкретным пунктом.
- Отчёт исполнителя, наблюдение автора и административное решение не заменяют друг друга.
- Старый callback, чужой дом, повтор команды и устаревший ML-ответ не меняют актуальное состояние.
- Новые рабочие HTTP endpoints остаются закрыты, пока нет проверенной аутентификации и проверки принадлежности.
- Не публиковать demo/no-db profiles. Не выдавать STUB за NLP, целевую метрику за замер, локальный тест за успешный CI/MAX-пилот.

## Где работать

Кирилл: `frontend/`, `backend/.../identity/`, `backend/.../max/`, сборка и интеграция.
Семён: `backend/.../cases/`, `reports/`, `observations/`, `notifications/`, `inference/`, SQL.
Никита: `ml/`, inference-контракт и ML-оценка. Общие контракты проверяют оба их потребителя.
Не добавлять пустые сервисы и интерфейсы. Новую реализацию размещать в пакете её владельца.

## Проверки и память

Команды: [docs/development.md](docs/development.md). Для БД нужен настоящий PostgreSQL; H2 не подтверждает миграции.
После значимой задачи обновить [PROJECT_STATE.md](docs/memory/PROJECT_STATE.md): факты, команда проверки, результат, оставшийся шаг. Причину изменения архитектуры записать в [DECISIONS.md](docs/memory/DECISIONS.md).
В [HANDOFF.md](docs/memory/HANDOFF.md) оставить краткую передачу следующему разработчику. Не копировать туда полный план или разговор. При параллельной работе автор передаёт итог задачи, общий статус и память обновляет Кирилл после интеграции; не затирать чужие строки. Применённые миграции V1/V2 неизменны, следующий номер координирует Семён.
Эти файлы - общая командная память по прямому запросу пользователя. Личные заметки, секреты, закрытые условия и персональные данные в Git не помещать. Личная долговременная карточка проекта остаётся в Obsidian.
