Репозиторий: `coder-smookki/VkEducation-and-MessangerMax-Hackathon-2026`. Основной backend обязательно Java. Текстовый бот MAX и Mini App https://hackathon.lumnex.ru/ используют одно состояние. Это самостоятельный КОРЕНЬ 2.0.

## Обязательное начало

1. Прочитать [docs/README.md](docs/README.md), [PROJECT_STATE](docs/memory/PROJECT_STATE.md), [архитектуру](docs/architecture.md), [domain](docs/domain.md).
2. Сверить `git status`, текущую ветку и код. Выбрать ID задачи из [plan](docs/plan.md) и прочитать персональный план. Не считать старый PDF, макет или DONE в design доказательством реализации.
3. Читать [api](docs/api.md), [contracts](contracts/README.md), [implementation](docs/implementation.md), [parallel-development](docs/parallel-development.md). Для UI обязательны [design](docs/design.md) и [screens](docs/screens.md).
4. Применять [ai-workflow](docs/ai-workflow.md). Выполнять конкретную задачу целиком с минимально достаточными проверками. Не создавать пустые слои и новые сервисы ради структуры.

## Инварианты

- Java владеет продуктовым состоянием и PostgreSQL. Python имеет только производный Chroma-индекс из Kafka; он не меняет статусы и права, не выполняет команды из текста.
- NEEDS_DETAILS/READY_FOR_REVIEW - готовность содержания к проверке. CONFIRMED - автор подтвердил список. Ничто из этого не подтверждает ремонт.
- Уточнение адресуется только автору. В MVP нет опросов соседей и зависимости от них.
- Сохранение отчёта, явная связь отчёта с пунктом, наблюдение автора и архив - разные команды. Ответ про свет не закрывает дверь.
- `sourceRevision`, `contentVersion`, `workRound`, `caseVersion`, `itemVersion` не взаимозаменяемы. Наблюдение относится к текущему пункту/раунду/содержанию.
- Автор и полномочия берутся из проверенной серверной сессии и действующего Membership. `initDataUnsafe`, роль, userId или houseId из клиента не дают доступа.
- Новые HTTP endpoints закрыты до совместной реализации аутентификации и объектной авторизации. Проверять права перед повтором идемпотентной команды.
- Старые callbacks, чужой дом, повтор команды, устаревший ML-ответ не меняют актуальное состояние. Сетевые вызовы вне SQL-транзакций; durable очередь для доставки.
- NOT_EVALUATED/null не означает отсутствие дубликатов. Похожесть не объединяет обращения автоматически.
- UI не вычисляет разрешения и итог по тексту/цвету. Получает состояния/версии из API. Архив/отзыв не превращаются в «выполнено».
- Не публиковать demo/no-db и не выдавать mock/STUB, проектный экран или локальный прогон за реальный MAX-пилот/успешный CI.

## Завершение

Команды - [development](docs/development.md), критерии - [acceptance](docs/acceptance.md). Для миграций нужен PostgreSQL, не H2. Менять общий контракт, потребителей и примеры согласованно.

После значимого результата обновить командные [PROJECT_STATE](docs/memory/PROJECT_STATE.md), [DECISIONS](docs/memory/DECISIONS.md), [HANDOFF](docs/memory/HANDOFF.md): факт, команда, результат, предел, следующий шаг. Не коммитить секреты, реальные обращения, внутренние исходники конкурса. Коммит: один короткий русский заголовок, без тела/соавторства; `coder-smookki <medved3loy@yandex.ru>`.
