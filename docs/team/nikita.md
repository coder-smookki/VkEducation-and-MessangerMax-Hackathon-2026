# Никита - ML/AI и оценка

Роль: сопоставление текущих текстов и проверка полезности. Основные файлы: `ml/app/analyzer.py`, `ml/app/contracts.py`, `ml/data/`, `ml/scripts/evaluate.py`. У ML нет подключения к предметной БД и права выполнять команды.

## Задачи по порядку

| ID | Часы | Зависимость | Действие | Приёмка |
|---|---:|---|---|---|
| N0 | 4-5 | Нет | Описать разметку и границы `Relation`, добавить 40 development-диалогов, отдельно templateGroup и спорные случаи | Два человека согласовали смысл меток; synthetic не названы реальными данными |
| N1 | 4-5 | N0 | Честный baseline: ручная форма и простые правила по категориям/месту; сохранить покрытие и ошибки | Формы, правила и NLI сравниваются по одному протоколу; abstention не выдаётся за 100% precision |
| N2 | 7-9 | N1 | Загрузить одну готовую NLI-модель, закрепить revision весов/токенизатора, сделать batched inference коротких пар | `mode=NLI` только после реального запуска; startup/readiness отражает готовность модели; веса не качаются на каждом запросе |
| N3 | 5-6 | N2, S4 | Сегментация ответа, evidence spans, политика отказа и несовпадения места | Для каждого item есть результат; точный фрагмент берётся из исходного текста; место/версия не угадываются |
| N4 | 7-9 | N3 | Заморозить пороги и собрать 60 новых диалогов другого автора; сравнить A/B/C и время проверки | Development и test не делят шаблоны; показаны precision, coverage, ошибки, размер набора и стоимость человеческих исправлений |
| N5 | 3-4 | N3 | Замерить CPU/RAM, p50/p95, короткие/длинные запросы и 5 параллельных задач | Указаны железо, модель, revision, настройки, число запросов; graceful overload; нет неподтверждённых обещаний скорости |

Ориентир: 30-38 часов + резерв. Можно начать до появления CRUD: в `contracts/examples` есть согласованный запрос и честный STUB-ответ.

## Первый час

`uv sync --frozen`, `uv run pytest`, `uv run python -m scripts.evaluate` из `ml/`.
Прочитать [протокол](../api.md). Сегодня analyzer всегда отказывается от вывода: 7 development-примеров и 14 пунктов проверяют подключение, не качество модели. Они не являются ни набором из 40, ни отложенным тестом из 60 диалогов.

## Выбор модели

Кандидат из отчёта: [MoritzLaurer/mDeBERTa-v3-base-mnli-xnli](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli). Начать с готовых весов без fine-tuning. Перед включением проверить текущую карточку, лицензию, mapping `id2label`, русский язык, формат пар и совместимость зависимостей через актуальную документацию. Эти зависимости пока намеренно не установлены.

Сначала раздельно определить отношение к предмету, место и смысл: сделано / запланировано / симптом сохраняется / противоречие / нет сведений. NLI score не равен вероятности физического ремонта. Не добавлять процент «ремонт выполнен» в UI.

Генеративный LLM и RAG не нужны для базового сравнения. Если позже согласованы генеративные черновики, оценивать их отдельным экспериментом; модель не вызывает инструменты записи и не получает закрытые данные без разрешения.

## Качество

Тестовые группы: частичный ответ, будущее/прошлое время, отрицание, другое место, одинаковые слова о другом объекте, цитата, опечатки, emoji, длинный текст, инструкция модели внутри ответа. Спорную интерпретацию помечать и передавать человеку.

Рабочая цель из PDF - precision предложенных связей около 0.95 с публикацией coverage и размера набора; это не полученный результат и не самостоятельное условие победы. Замерять всё время правильного разбора, включая чтение и исправление подсказок. 60 диалогов недостаточно для утверждения production-качества.

## Передача

Семёну: OpenAPI, пример ответа, modelVersion, границы входа, время ожидания и перегрузки. Кириллу: смысл каждой подсказки и нейтральные подписи. Команде: воспроизводимый файл результатов, ошибки, ограничения и решение, чем NLI полезнее baseline.
