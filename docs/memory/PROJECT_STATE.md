## Чего пока нет и что блокирует рабочий продукт

Настоящий MAX-транспорт: формат update и callback не подтверждён живым ботом, поэтому разбор отправителя и ключ дедупликации написаны терпимо к нескольким формам, а нераспознанный update остаётся во входящем ящике вместо толкования догадкой. Отправка закрыта интерфейсом MaxSender с реализацией UnconfiguredMaxSender, которая **отказывает**, а не сообщает об успехе: заглушка не доказательство доставки, и настоящих delivery receipts у нас нет. G2 (два реальных аккаунта проходят QA-E01..E09) не пройден. Кнопки в боте не сделаны - вопрос о наблюдении задаётся текстом; правило «старая кнопка не меняет новый раунд» при этом соблюдается сервером, потому что раунд хранится в состоянии диалога. Рабочий UI и отдельная release-конфигурация уже есть, подтверждённого deployment пока нет.

Вход через MAX проверен независимыми HMAC-векторами и HTTP-тестами, но не на реальном web/mobile MAX: нужен HTTPS-стенд, и он же нужен, чтобы MAX вообще мог постучаться в webhook. ownerDisplayName и displayName в /me возвращают null - колонки имени в app_user нет. Отчёт в MVP вводит только диспетчер: сценарий EXECUTOR требует назначения исполнителя, которого нет. Сравнение текста отчёта с пунктами подключено, но по умолчанию выключено (ANALYSIS_ENABLED=false) и на живом Python в Compose ещё не прогонялось; UI поддерживает READY с точной цитатой и ручной выбор; эта ветка проверена на fixtures, живой Python анализ на release-стенде не проверен. Правка и подтверждение списка пунктов в чате работают текстовым форматом из трёх полей, а не разбором свободной фразы: разбор свободной фразы на пункты по-прежнему STUB - S-06 касался сравнения отчёта, а не приёма. Если у человека несколько домов, бот отправляет его создавать обращение в приложение вместо выбора дома в чате.

Для выпуска остаются части QA-R, не закрываемые кодом backend: R07 (устройства, K-05/K-06), R08 (чистая сборка с замером, вместе с Кириллом), R09 в части HTTPS, закрытых портов Python и БД и выключенного demo на release-конфигурации. Настоящий smoke R05 - BLOCKED до транспорта MAX; управляемый мок пройден тестами. Нагрузка измерена на ноутбуке, а не на стенде. Переменные стенда добавлены в compose.yaml и .env.example: без MAX_WEBHOOK_SECRET маршрут webhook не существует, без MAX_WORKERS_ENABLED=true воркеры не запускаются, без ANALYSIS_ENABLED=true отчёты не анализируются.
