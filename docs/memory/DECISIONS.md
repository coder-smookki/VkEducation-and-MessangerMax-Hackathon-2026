# Существенные решения

Актуализировано 26.09.2026. Состояние реализации отдельно в PROJECT_STATE; принятое решение не означает готовый код. Детальная история прежних редакций доступна в Git.

| Решение | Причина и цена |
|---|---|
| Java владеет командами/состоянием/PostgreSQL; Python только подсказывает | Одна граница прав и переходов; JSON/сходство не авторизация |
| Пункт, отчёт, link, наблюдение, admin - раздельные факты | Ответ о свете не закрывает дверь; нужны явные команды/версии |
| Автор подтверждает состав, уточнение только автору | Нет опросов соседей и зависимостей MVP от них |
| DRAFT редактируется, CONFIRMED состав обычным PATCH не меняется | Не переносить старые наблюдения на другой смысл; отзыв с причиной сохраняет total |
| Приём/nextAction обязательны; архив в Must по одному item | Макеты должны отражать реальный процесс; нужны миграции/DTO, D09/D10 исправлены |
| Семён Java/Python/бот, Кирилл frontend/release, София QA | Новый состав пользователя; прежние персональные назначения больше не действуют |
| Общие fixtures позволяют параллельную разработку | UI не ждёт весь backend, но fixture-проверка не означает интеграцию |
| Cookie HttpSession +CSRF как первый вариант | Простота одной Java-инстанции; совместимость MAX web/mobile проверить рано, при необходимости выбрать один другой транспорт |
| Auth проверяет raw URL-decoded значения без пересериализации user JSON | Согласование с официальным алгоритмом MAX; независимые HMAC-векторы, role не берётся из initDataUnsafe |
| Состояние/audit/command result/outbox в одной транзакции | Устойчивость к повторам; внешняя сеть вне SQL, inbox до ACK, worker lease необходим |
| RULES/manual вместо обязательного LLM/NLI | У команды один backend-инженер; качество доказывать holdout; смешанные субъекты разведены в S-06 (rules-baseline-v2) |
| Kafka/Chroma сохранены как существующее расширение | Индекс производный, не права; история replay и монотонные snapshots, качество русского поиска ещё не измерено |
| MAX-палитра с явной адаптацией контраста | Пользователь запросил стиль MAX; #007AFF с мелким белым текстом недостаточен, #0066CC сохраняет оттенок и читаемость |
| Не ставить MAX UI с несовместимыми exact peers через force | Проверенный source требует React 19.2.8, приложение 19.3.0; semantic CSS tokens избегают необоснованной смены стека |
| Локальный дизайн и production код различаются | Каталог/дизайнерские роли/localStorage текста не переносить как бизнес-логику |
| hackathon.lumnex.ru, один origin, root/max/webhook | Актуальное уточнение пользователя; основной сайт lumnex.ru не затрагивается |
| В Git docs/contracts/design, внутренний output исключён | Агентам достаточно открытой самодостаточной спецификации; исходный токен/закрытые условия не публикуются |
| Коммит только коротким русским заголовком, без trailers | Прямое указание пользователя; author/committer coder-smookki <medved3loy@yandex.ru> |
| Приём - отдельный факт, не меняющий workStatus/observation | Принято не значит начато и тем более не значит починено; receipt живёт отдельно от работ |
| Следующий шаг поднимает caseVersion и itemVersion, но не contentVersion и не workRound | План не содержание и не отчёт; две версии у пункта разводят конкурентные правки разных фактов |
| Конфликт версий решает правило доступа самой команды, а не общий помощник | Помощник считал актора автором и отдавал диспетчеру 404 вместо 409; найдено чтением, закреплено тестом |
| Очередь диспетчера - пересекающиеся фильтры по фактам, не новый исключающий статус | Обращение может одновременно ждать приёма и плана; исключающий статус потребовал бы переходов и врал бы |
| queueState только диспетчеру внутри разрешённого дома, курсор привязан к дому и фильтру | Очередь - рабочий инструмент, а не второй способ листать свои обращения; чужой курсор не переносит выборку |
| Текст отчёта и связь с пунктом - разные команды | «Лампу заменили, дверь заменим» не должно закрывать дверь; решает человек, а не разбор текста |
| Раунд открывает только подтверждённая связь, и только у своего пункта | Работы по одному пункту не переносятся на соседний; наблюдение относится к раунду, поэтому сбрасывается вместе с ним |
| Связь сторожат три значения: itemVersion, contentVersion, workRound | Разъехаться может каждое по отдельности; один общий счётчик заставил бы выбирать между ложными конфликтами и незамеченными |
| Набор связей применяется атомарно, без частичного результата | Диспетчер подтверждает решение целиком; половина набора оставила бы обращение в состоянии, которого никто не выбирал |
| Повтор пары отчёт-пункт запрещён, новые сведения - новым отчётом | Новый ключ идемпотентности не обходит правило; иначе история работ перестаёт быть историей |
| Отчёт в MVP вводит диспетчер, EXECUTOR отложен | Назначения исполнителя нет, «по назначению» нечем проверить; основной путь обслуживают автор и диспетчер |
| Отзыв и архив - разные исходы в прогрессе | Отзыв снимает вопрос и идёт в withdrawn, архив закрывает его административно и остаётся в remaining; иначе архив читался бы как ремонт |
| Административное решение необратимо, возврата нет | Обратный переход пришлось бы объяснять в истории и в праве; новая проблема - новый пункт, это честнее и дешевле |
| Право на решение делится по ролям: архив диспетчеру, отзыв автору | Отзыв - слова автора о своей заявке, архив - административное действие службы; одна ручка с двумя правилами доступа вместо двух команд |
| Окончательность решения проверяется и в SQL, не только в домене | Между чтением состояния и записью успевает вклиниться второй диспетчер; WHERE administrative_status = 'ACTIVE' делает это свойством базы, а не тайминга |
| История отдаёт белый список полей, а не payload аудита | Сегодня в payload только идентификаторы, но завтра туда положат текст; список полей защищает от будущего, а не от настоящего |
| Курсор истории сравнивает пару (created_at, id) | now() одинаков для всех событий одной транзакции; сравнение только по времени теряло бы или дублировало события на границе страницы |
| Недоступное обращение отвечает 404, а не 403 | 403 сообщил бы, что такое обращение существует; в контракте у истории 403 поэтому не заявлен |
| Уведомление несёт только идентификаторы, без пользовательского текста | Между постановкой в очередь и отправкой доступ могут отозвать; текст, попавший в очередь, отзыв доступа уже не спасёт |
| Право получателя проверяется перед отправкой, а не при постановке | Очередь живёт во времени; отменённое уведомление остаётся с пустым sent_at, потому что отмена - не доставка |
| Счётчик попыток растёт при выдаче события, а не при провале | Падение воркера посреди обработки иначе крутило бы одно событие вечно; исчерпавшее попытки остаётся видимым, а не помечается обработанным |
| Одна очередь на уведомления и ответы бота, case_id необязателен | Вторая таблица дала бы вторую реализацию аренды, повторов и backoff, и они бы разъехались |
| Ответы бота идут через очередь, ключ производный от ключа события | HTTP внутри транзакции запрещён; при повторной доставке update ключ совпадает, и второго ответа человек не получает |
| Состояние диалога на сервере хранит раунд, о котором спросили | Так правило «старая кнопка не меняет новый раунд» выполняется без кнопок; ответ после нового раунда отклоняется, а не применяется к чужому раунду |
| Нераспознанный update остаётся во входящем ящике, а не толкуется | Формат MAX живьём не виден; застрявшие события покажут настоящий формат, а «не понял» в ответ на всё теряло бы сообщения молча |
| Отправщик-заглушка отказывает, а не сообщает об успехе | Очередь, помечающая недоставленное отправленным, перестаёт быть доказательством; delivery receipts от заглушки не бывает |
| Пул соединений в тестах ограничен двумя | Контексты Spring кэшируются и не отдают пулы; десять соединений на контекст исчерпывали max_connections, и падал произвольный чужой тест |
| Время очередей берёт база, а не JVM | Аренду ставит одна сторона, а проверяет другая; при двух часах истечение аренды зависело от расхождения часов, и тест плавал |
| Анализ отчёта - фоновая задача, а не часть сохранения | Сохранение не должно ждать Python и не должно падать вместе с ним; задача в той же транзакции не теряется |
| Анализ выключен по умолчанию | Демо, CI и стенд без Python ведут себя как раньше и честно отвечают MANUAL_REQUIRED |
| Подсказка хранится с версиями пунктов, STALE вычисляется при чтении | Пункт меняется после анализа; хранимый STALE пришлось бы обновлять из каждой команды и однажды забыть |
| Ответ STUB хранится, но отдаётся как MANUAL_REQUIRED | Заглушка ничего не прочитала; READY над ней выглядел бы как анализ |
| После трёх неудачных попыток - MANUAL_REQUIRED, а не вечный QUEUED | Ручной путь должен быть виден сразу; бесконечная очередь выглядит как «ещё думает» |
| Анализатор читает по частям фразы; два пункта в одной части - воздержание | Ложное «сделано» дороже пропуска: его подтвердят, не читая; на регрессии v1 ошибался в 7 из 12, v2 - ни разу |
| Holdout пишет София, а не автор правил | Фразы, написанные после знакомства с правилами, проверяют правила, а не язык |
| Верхние метрики evaluate - только development | Смешение наборов прятало бы и провалы регрессии, и отсутствие holdout |
| Ошибка API - problem+json с постоянным code и без текста исключения | Клиенту нужен код, чтобы выбрать реакцию; текст исключения и эхо ввода могут нести пользовательские данные и внутренности |
| /error открыт только для пересылки после сбоя | Под denyAll каждая 400/404/500 превращалась в 401; прямой запрос /error по-прежнему отклоняется |
| Неизвестный маршрут - 404 вошедшему, 401 анониму | Аноним не узнаёт, какие маршруты существуют; вошедшему пустой 403 ничего не объяснял |
| Непойманное исключение пишет в лог фильтр, без сообщения | Сообщение может содержать текст пользователя или значения из SQL; класса и кадров достаточно, чтобы найти ошибку по requestId |
| requestId клиента принимается, только если он безопасного вида | Тестировщик находит свой запрос по своему id; произвольная строка могла бы подделать строку лога или раздуть её |
| Тело API ограничено 256 КиБ до чтения, chunked отклоняется | Самый большой честный запрос около 55 КиБ; размер chunked-тела нельзя проверить заранее, а клиентам он не нужен |
| Размер страницы вне диапазона - 422, а не урезание | Молча урезанная страница выглядит как конец списка |
| Ответы MAX делятся на лимит, недоступность и отказ | Повторять отказ бессмысленно, а повторять лимит сразу - вредно; 401 считается недоступностью, потому что это наш токен |
| 429 откладывает всю пачку и возвращает ей попытки | Лимит у бота, а не у сообщения; отправка остатка в тот же лимит сожгла бы попытки впустую |
| failed_at - явное состояние, но без ограничения в базе | Недоставленное находится одним запросом; ограничение сломало бы тесты, паркующие чужие строки через sent_at |
| Восстановление проверяется в отдельную базу | Проверку можно запускать на рабочем стенде в любой момент; «не стирать volume ради зелёного теста» |
| Нагрузка идёт через настоящий вход и CSRF | Иначе измеряется не тот путь, по которому ходят пользователи; скрипт на стандартной библиотеке запускается без установки |
| Контракт и маршруты сверяются тестом в обе стороны | Маршрут без описания заставляет фронтенд угадывать, описание без маршрута обещает несуществующее; ContractRoutesTest нашёл шесть первых сразу |
| api.md описывает только работающее, отсутствующее - отдельным списком | Старый документ обещал назначение исполнителя, настройки уведомлений, 429 и 503, которых нет; UI строился бы на них |
| RESIDENT - только через приглашение, DISPATCHER - только шагом оператора после первого входа | Ни одна роль не берётся из запроса; seed использует тот же путь, что и живые пользователи |
| Код приглашения печатается один раз, в базе только SHA-256 | Утечка базы не выдаёт действующих кодов; потерянный код выпускается заново, а не восстанавливается |
| Анализ и бот в кандидате выключены | Анализатор не проверен на holdout, отправитель MAX - заглушка; включённые, они изображали бы работу, которой нет |
| SHA запущенной версии открыт в /actuator/info, больше ничего | Без этого нельзя доказать, что проверяется именно сданная версия; SHA не секрет, а детали health и env остаются закрыты |
| Kafka и индекс похожих не запускаются в кандидате, код остаётся | Функция не в обязательном пути и цепочка публикации неполная; удаление за три дня до сдачи - 2-4 часа и риск для CI, профиль - две строки |
| CI включает профиль similar явно | Тесты Kafka и Chroma должны проверять функцию, а не молча пропускаться, пока её нет на стенде |
| Demo выключается переменной окружения, а не правкой файла | Разработчику demo нужен, стенду нельзя; одна переменная SPRING_PROFILES_ACTIVE=release и проверка stand_smoke |
| Smoke стенда не засчитывает недоступный адрес | «Нет ответа» - не «закрыто» и не «без деталей»; иначе упавший стенд выглядел бы частично исправным |
| Числа для дежурства читаются из базы скриптом, а не публичным маршрутом | Оператор сидит на машине стенда; новый открытый маршрут был бы ещё одной поверхностью для QA-R09 |
Источники оформления и проверки: [research](../research.md), [design](../design.md). Условия готовности: [acceptance](../acceptance.md), календарь [plan](../plan.md).
