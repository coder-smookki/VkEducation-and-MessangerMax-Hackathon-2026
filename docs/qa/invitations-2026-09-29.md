# Подключение учебных домов - 29.09.2026

## Подтверждённая причина

В MAX на экране доступа введён houseId A `f8c816d6-87a3-4bc6-ac66-38af18a263aa`. Это идентификатор дома, не приглашение. Его SHA-256 отсутствует в house_invitation, поэтому INVITATION_REJECTED является правильным отказом. ID дома сам по себе не должен выдавать право доступа.

По серверной PostgreSQL у четырёх выданных одноразовых кодов: правильный дом A/B, consumed=false, срок до 06.10.2026 22:40 МСК, failed_attempts=0 из 5. В момент диагностики: 2 настоящих app_user, 0 membership. Приглашения не создавались заново и не расходовались автотестом; БД не очищалась.

Логи backend/web за последние 2 часа: requestId `063743f3-2500-436c-9c9d-76875d14c021` не найден; Unhandled failure=0. Обычные доменные отказы не логируются фильтром, access_log web отключён. Не утверждаем, что нашли именно этот HTTP-запрос в логах. Причина подтверждена введённым значением, кодом InvitationService/Repository и действующими данными БД.

## Что сделать пользователю

1. Открыть Mini App из бота MAX, выбрать «Доступ к дому».
2. Вставить приватный код приглашения целиком, без пробелов. Не вставлять UUID из seed-таблицы.
3. Нажать «Подключить дом». Ожидание: «Дом успешно подключён!», дом в списке, роль «Житель».
4. Нажать «Готово» и проверить список обращений своего дома. Пустой список после согласованной очистки допустим.
5. Для другого аккаунта использовать отдельное неиспользованное приглашение. Диспетчер назначается отдельно по проверенному MAX-аккаунту; код Жителя не повышает роль.
6. При новом отказе передать requestId и время, не публиковать код в Git. Уже использованный код не предназначен для повторного подключения другого аккаунта.
