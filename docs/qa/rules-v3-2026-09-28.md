## Решение и цена безопасности

Выбран консервативный `rules-baseline-v3` в существующем Python-сервисе. Он распознаёт ограниченный набор ясных утверждений и воздерживается при непонятной области действия, условии, вопросе, цитировании, опровержении или неоднозначной привязке к пунктам. Новых библиотек, моделей и сервисов нет. Генеративный LLM, parser и NLI рассмотрены как будущие варианты, но не внедрялись и не измерялись: сравнение ниже относится только к реально выполненным трём алгоритмам.

Основной рабочий сценарий остаётся ручным: сохранить отчёт → выбрать конкретные связи → отдельно получить наблюдение автора. Даже точный `REPORTED_DONE` означает только утверждение в тексте. Ремонт он не подтверждает.

**Это улучшение безопасности, а не универсального понимания языка.** На сложном синтетическом challenge v3 даёт содержательную метку лишь для 12/97 пар, остальные 85 оставляет человеку. Из них 55 имеют содержательную gold-метку, то есть это осознанные пропуски. Поэтому 12/12 верных выданных подсказок нельзя называть «100% accuracy»: строгое совпадение всех меток с gold составляет 42/97. Для `PLANNED` и `CONFLICT` в этом challenge v3 не выдал ни одной метки; их качество на нём не доказано. Положительные примеры этих классов есть в development/unit tests.

Первоначальное предложение предполагало точный локальный разбор любых операторов. Реализация намеренно уже: неподдержанное условие/цитата/вопрос во всём отчёте могут отключить все его подсказки. Это теряет и корректную соседнюю фразу, но не вырывает её из неразрешённого контекста. Снять такой отказ допустимо только после отдельных размеченных проверок области действия, а не добавлением исключения под один пример.

## Как сравнивали

1. Сохранена прежняя v2 в `ml/scripts/evaluation/rules_v2.py`, только для воспроизведения сравнения. Production импортирует одну v3.
2. Минимальная правка `guarded-v2` добавляет общий запрет на условия «если/бы», вопросы и цитаты, оставляя прежнее сопоставление. Это контрольный вариант в `ml/scripts/compare_rules.py`, не доступный режим сервиса.
3. Другой агент создал challenge без чтения реализации. До первой оценки зафиксированы данные и первая v3.
4. Сохранена первая оценка. Она выявила ложный DONE в `rules-v3-043`: инструкция перед двоеточием терялась при разборе. Исправлен общий класс неразобранной вводной области. Дополнительный review нашёл одиночное «нет», неполный разбор длинного номера этажа и слишком широкий prefix-match порядковых слов; добавлены адресные регрессии.
5. Повторная оценка использует **тот же неизменённый challenge**, но теперь это regression-набор. Не выдаётся за второй независимый holdout.

Challenge: 64 отчёта, 97 пар, 31 группа; [данные](../../ml/data/challenge-v3.jsonl), [разметка](../../ml/data/challenge-v3.md). Development (16 отчётов, 29 пар): v2 и guarded-v2 - 16/29 содержательных, 16/16 точных; v3 - 10/29, 10/10 точных. Это известный разработчику набор, не независимое доказательство качества.

Ни один из наборов не является человеческим holdout из реальных обращений. Ноль ложных DONE на 97 синтетических парах не гарантирует ноль ошибок на произвольном вводе. Для расширения покрытия нужен отдельный набор, размеченный минимум двумя людьми, с заранее согласованной политикой спорных меток. До него не повышать заявления о качестве и не автоматизировать предметные решения.

## Изменения Java и UI

- `AnalysisPolicy` допускает только `RULES + rules-baseline-v3`; структурная проверка ответа `SuggestionValidator` сохранена.
- Worker хранит непригодную версию для аудита, но не выставляет READY. `NLI` с таким же номером версии тоже не принимается.
- `getSuggestions` сначала проверяет доступ. Выключенный анализ возвращает MANUAL_REQUIRED для старых READY/QUEUED; старый v2 и несовпадающие версии снимка возвращают STALE без payload.
- Чтение не меняет jobs, links, раунды, наблюдения и историю. Пересчёт старых отчётов не запускается при GET.
- Mini App не показывает кэш до успешного свежего чтения, скрывает его при ошибке, проверяет mode/version/ID/версии/цитату. Ручная связь доступна независимо от анализа.
- При открытии экрана и возвращении фокуса подсказка перечитывается. READY перечитывается раз в 30 секунд при активном наблюдении. Это не мгновенная push-инвалидация; при отсутствии сети новые данные получить невозможно.
- Поля и значения HTTP-контрактов сохранены, обновлён только пример версии. DATA-API основного пути не зависит от готовности анализа.
