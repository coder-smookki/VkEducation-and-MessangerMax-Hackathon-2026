Дополнительный полигон DATA-API после PR #15: `python3 scripts/check_data_api.py --runs 2 --report <вне-Git>/real-api.json`. Всегда собственный loopback Compose, реальные Java/PostgreSQL, никакого публичного target. **81/81 PASS**, [пределы](data-api.md). Это дополнение к `check_miniapp.py --analysis`, а не его замена и не физический MAX.

Дата: 28.09.2026, Europe/Moscow. Задачи K-06/K-08, Q-06. Это воспроизводимая автоматическая часть приёмки, а не подтверждение всех ручных карточек или готовности MAX-пилота.

Последний выполненный повтор - [протокол 28.09](local-playground-2026-09-28.md): четыре исправления RULES и усиление двух UI-проверок, 6 PASS с Python, 4 PASS + 2 SKIP без него, сохранённые FAIL/снимки/хеши вне Git. Карта ниже по-прежнему показывает границы покрытия, а не отметку выполнения всех карточек.

Из корня репозитория на машине с Docker Compose, Node.js и установленными frontend dependencies/Chromium:

```sh
python3 scripts/check_miniapp.py --analysis
```

Однократная подготовка зависимостей: `npm --prefix frontend ci`, затем `npx --prefix frontend playwright install chromium`. Скрипт не устанавливает пакеты сам. Без `--analysis` запускается прежний ручной режим: `ANALYSIS_ENABLED=false`, Python не поднимается, четыре базовых integration-теста выполняются, два новых помечаются skipped. С `--analysis` включены профиль Compose `analysis`, `ANALYSIS_ENABLED=true` и все шесть integration-тестов. Ни один skipped не считается PASS.

Каждый запуск создаёт отдельный проект `koren-ui-check-*`, новую PostgreSQL и случайные тестовые секреты. Web доступен только через `127.0.0.1` на свободном порту. MAX workers выключены; никаких сообщений пользователям нет. `finally` удаляет только этот Compose-проект и его тома, приватный env удаляется отдельно. Код не принимает адрес чужого/публичного стенда. Публикация, seed production, настоящий бот и серверный restart сюда не входят.

## Что исполняет команда

1. Собирает текущие release Dockerfiles и запускает nginx, Java, PostgreSQL, а с флагом ещё Python RULES. Локальные кэши допускаются; время не объявляется холодной сборкой.
2. Выполняет существующие четыре теста в `frontend/tests/integration.spec.ts`: профиль после reload; автор → приём → отчёт → ручная связь света → RESTORED/1 из 2 → архив с повтором потерянного ответа; приглашение/отрицательные наблюдения/отзыв/logout; границы proxy и недоступный backend.
3. С флагом добавляет две проверки реальной цепочки UI → Java → durable analysis job → HTTP Python → сохранённая подсказка → UI. Условный текст не даёт REPORTED_DONE; смешанный текст даёт отдельные REPORTED_DONE света и PLANNED двери с точными Unicode-цитатами. Проверяются `mode=RULES`, `modelVersion=rules-baseline-v3`, версии, IDs и выполненная попытка job в PostgreSQL.
4. Проверяет отсутствие автоматического выбора, links, нового раунда, наблюдения и изменения progress после анализа. Только явная ручная связь меняет свет; дверь остаётся прежней, без авторского наблюдения прогресс остаётся 0 из 2. Проверки axe/геометрии и снимки выполняются на настоящих ответах Java.

В integration нет подмены ответов продуктового API. Вход MAX подписывается случайным локальным ключом, SDK MAX и изображение тестового профиля заменены локальными fixtures. Существующий тест неизвестного исхода сначала выполняет настоящую команду через `route.fetch()`, а затем обрывает её ответ; это внедрение сетевого отказа, не фиктивный успех API.

## Артефакты и версия

Скрипт печатает приватный каталог системной временной директории `koren-ui-results-*` вне Git. Он остаётся после cleanup и содержит:

- `result.json`: режим, HEAD, dirty flag, digest, loopback URL, результат этапов/cleanup и длительность.
- `source-before.json` / `source-after.json`: SHA256 фактических working-tree bytes каждого tracked и non-ignored untracked файла, executable bit/ссылка и общий digest. Содержимое файлов и секреты не копируются. Gitignored build/cache/временные файлы не входят в digest; это явно записано в scope. HEAD сам по себе не выдаётся за собранную dirty-версию.
- `playwright.json`: результаты отдельных тестов, skipped/failures и JSON-attachments новых сценариев с синтетическими подсказками/job/progress.
- `screens/manifest.json` и PNG: route без UUID, viewport, theme, размер текста; `test-results/` содержит дополнительные снимки и снимки падений. Traces с launch/cookies не сохраняются.

При изменении исходников между снимками итог `INCONCLUSIVE_SOURCE_CHANGED`, exit code не ноль. При неудачном cleanup итог `FAILED_CLEANUP`; имя только собственного проекта есть в `result.json`. Аварийное завершение процесса/машины может не выполнить `finally` - такой запуск нельзя считать успешно очищенным. Каталог результатов временный: для длительного хранения скопировать его в приватное хранилище артефактов, не в Git.

## Как ChatGPT самостоятельно проверяет и исправляет

Не нужен дополнительный бот или сервис с доступом к рабочей БД. Агент работает с репозиторием, shell и Playwright; полигон создаёт среду и доказательства. Достаточный цикл:

1. Прочитать актуальное состояние/план и выбранные QA-карточки. Проверить git status, владельцев файлов и воспроизводимый дефект. Не принимать чужую правку за свою.
2. Завершить изменения и заморозить исходники на время прогона. Запустить минимальный тест затронутого инварианта, затем нужный режим полигона; не редактировать код параллельно со сборкой.
3. Прочитать exit code, result/playwright JSON, errors и относящиеся к сбою снимки. Разделить ошибку продукта, инфраструктуры и теста. Проверить реальный контракт перед исправлением тестового запроса.
4. Сохранить первый FAIL. Воспроизвести его узким тестом, исправить ответственный слой, повторить этот тест, затем затронутую сквозную цепочку. Если изменён общий клиент/контракт - прогнать полный соответствующий suite. Не менять gold/ожидания ради зелёной строки и не скрывать flakes автоматическими повторениями до успеха.
5. Убедиться в cleanup только собственного проекта. При провале очистки восстановить её по точному имени из result.json; не использовать глобальный prune/down чужих стеков.
6. Обновить командный протокол: какие QA-инварианты выполнены, реальные counts/skips, digest, режим, причина исправления и оставшиеся ручные проверки. Полноту карты не выводить из количества зелёных тестов.
7. Остановиться, когда нужные проверки прошли и нет нового дефекта. Физический MAX/G2, права реальных людей, публикация и реальные сообщения не выполняются скрыто из локального раннера.
