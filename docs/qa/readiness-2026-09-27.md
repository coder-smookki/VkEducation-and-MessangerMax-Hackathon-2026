## Найденные дефекты и незакрытые проверки

### Качество RULES: ложноположительное выполнение

Воспроизведено настоящим HTTP `POST /internal/v1/compare` с `KOREN_COMPARE_ANALYZER=rules`. Ответ 200, режим RULES, `ANALYZED`, результат по свету `REPORTED_DONE` для всех трёх текстов:

- `Если лампу заменили, сообщите диспетчеру.`
- `В прошлом отчёте написано: «Лампу заменили». Это была ошибка.`
- `Лампу на третьем этаже заменили? Пока сведений нет.`

Условие, опровержение прежней цитаты и вопрос не являются утверждениями о текущем выполнении. Во втором случае evidence оставляет цитату без опровержения. Причина находится в `ml/app/features/inference/rules_analyzer.py`: выбор `done` по совпадению маркера без достаточной проверки контекста. UI выводит подсказку в `frontend/src/features/reports.tsx`.

**Автоматического закрытия обращения не обнаружено:** явная связь диспетчера и наблюдение автора остаются отдельными командами. Тем не менее, по Q-06 ложноположительный вывод блокирует включение подсказок до исправления и независимого набора либо отключения анализа с ручным путём. На сервере сейчас `ANALYSIS_ENABLED=true`; аудит флаг не менял. Встроенные development/regression метрики не являются holdout, наши новые примеры после чтения правил тоже не являются слепой приёмкой.

### Seed: проверять весь приватный JSON до SQL

- P2: `isinstance(max_id, int)` принимает `true`. При `dispatcher: true` apply успевает создать дома и приглашение, затем получает SQL-ошибку `bigint = boolean`. Нужна проверка точного типа/диапазона всех ID до записи.
- P3: валидный JSON неверной формы (`null`, список, число, строка) приводит к `AttributeError` на `.get`, а не понятному сообщению. Новый обработчик битого JSON покрывает синтаксис, но не форму.
- Apply не атомарен целиком: сбой второго дома оставляет первый; повтор восстанавливает ход. Не обещать отсутствие частичных изменений. На корректном объекте с положительными целыми разными ID основные apply/check и права прошли проверку.

### Другие границы продукта

- Ограничение частоты запросов приглашения пока отсутствует; это прямо отмечено в `docs/implementation.md`, тогда как QA-A04 требует его. Одноразовость кода и лимит использований не заменяют rate limiting. Этот пункт нельзя записать PASS.
- Extraction возвращает STUB/пустые предложения, автор добавляет пункты вручную. Clarify и пользовательский поиск похожих не подключены. Kafka/Chroma в release выключены; внутренняя успешная интеграция не доказывает пользовательскую функцию.
- В текстовом боте нет правки/удаления пункта и выбора между несколькими домами; для них используется Mini App. Не заявлять весь сценарий как chat-only.
- Физические устройства, VoiceOver/TalkBack, независимый holdout, нагрузка на согласованной среде и повторяемый доступ оценщика остаются отдельной приёмкой. Автоматические результаты выше их не закрывают.
