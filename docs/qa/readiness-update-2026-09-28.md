## Исправленные неточности старой инструкции

- Бывший server `2833443` и dirty digest не названы новым релизом; текущий runtime SHA отдельно от последующего documentation HEAD.
- «Остановка БД уже проверена» заменено на точный факт: integration останавливает backend; PostgreSQL outage остаётся.
- Новый key при повторном приёме уже принятого обращения может дать 422 INVALID_TRANSITION; stale-version проверяется на допустимом переходе. Не любой отказ обязан быть 409.
- AFTER_REPORT требует текущую явную REPORTED_DONE-связь; READY или просто сохранённый отчёт не подходят.
- Восстановление Python принимается только по новому валидному READY/RULES/v3; продолжающийся отказ не считается успешным recovery.
- Для `load.py` одного `--api-url` недостаточно: `COMPOSE_FILE`, `COMPOSE_PROJECT_NAME`, `COMPOSE_ENV_FILES` и тестовый `--bot-token` должны относиться к той же изолированной среде.
- Не обещается сохранение несохранённого текста при закрытии WebView, внешняя exactly-once доставка MAX, 100% языковая точность или выполненный G2 по Chromium.

София возвращает PASS/FAIL/BLOCKED/NOT_RUN по каждому оставшемуся действию с SHA, датой, ролью/клиентом и доказательством. Условия и исходники замораживаются на время прогона; первый FAIL сохраняется, исправляется ответственный слой, затем выполняется подходящий retest. Публичный стенд не используется для отказных/нагрузочных экспериментов.
