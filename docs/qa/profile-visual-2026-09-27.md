## Исправления

- Профиль получает имя, username и фото из подписанного MAX initData после серверной проверки. `MaxProfile` хранится в существующей сессии; login, `/me` и claim возвращают одинаковые nullable поля. Principal UUID, Membership и CSRF не менялись. SQL-миграций нет.
- Фото загружает браузер без Referer; Java не скачивает URL. Некорректные optional данные не ломают вход. CSP разрешает изображения только с существующих источников и проверенного CDN `https://i.oneme.ru`. При отсутствии/ошибке фото остаётся SVG; отсутствующий username не придумывается. Новые сведения MAX появляются при следующем входе.
- Исправлена причина наложения лупы: специфичность общего CSS сбрасывала левый отступ search input. Проверены разные размеры текста и viewport. Значок обновления заменён симметричным SVG.
- Стрелки назад и маркеры всех disclosure-секций Mini App используют общий SVG Icon. Native `details/summary`, клавиатура, accessible name и ленивая загрузка истории сохранены. Обычная пунктуация и тексты пользователей не заменяются.
- На 320px шаги формы размещают номер над подписью, а нижнее меню сохраняет слова целиком. Размер крупного текста не уменьшается; при экстремальном масштабе доступна внутренняя прокрутка.
- Архив/отзыв использует общий Notice: текст больше не сжимается в узкие колонки. Просроченный срок шага не выдаётся за отсутствие более свежих сведений.
- Первый HTTP-запрос анализа показывает ожидание, затем действительный результат или ошибку. Ручная проверка связей доступна во всех состояниях. Ожидание не объявляется отказом.

## Источник данных

В `frontend/src` нет импортов demo/mock/fixtures/design. Все продуктовые чтения и команды идут через `api/client.ts` в `/api/v1` с серверной сессией. Успех отображается после ответа команды. `localStorage` хранит настройки вида, а не обращения/права. Поиск и счётчики ограничены загруженными карточками, что явно подписано при пагинации.

Фотографии обращений, произвольные исполнители и другие отсутствующие API-функции из рекламных макетов не имитируются. Иллюстрации пустых состояний являются оформлением, а не сведениями о доме. Сохранение отчёта, его связь, наблюдение, архив и отзыв остаются разными командами.

## Как повторить проверку

`npm --prefix frontend test` проверяет изолированные UI-состояния, включая ошибки и задержки, через явно тестовые HTTP fixtures. Они не входят в production bundle.

`KOREN_QA_CAPTURE=/absolute/path python3 scripts/check_miniapp.py` собирает настоящий nginx/Java/PostgreSQL17 в отдельном случайно названном Compose-проекте. В этом проекте создаются синтетические пользователи/обращения, а все ответы продуктового API настоящие. MAX launch подписывается случайным тестовым ключом; сообщения в MAX не отправляются. Скрипт удаляет только созданные им контейнеры и volume в `finally`. PNG и manifest пишутся вне Git.

Сквозные сценарии: профиль/cookie/reload/CSP; автор → исходный текст → пункты → подтверждение → приём диспетчером → следующий шаг → отчёт/связь → частичное наблюдение → архив; приглашение → отрицательные наблюдения → отзыв без уменьшения знаменателя; недоступность backend и закрытые proxy-маршруты. Визуальные точки охватывают все 12 действующих route patterns, 48 состояний, 320/390/1440px, светлую/тёмную темы и крупный текст. В каждой точке проверяются горизонтальное переполнение, геометрия контролов, axe WCAG2A/AA/2.1AA и попадание указателя в несколько доступных контролов.

Снимки: `~/Desktop/ДомПульс QA 27-09-2026/real-api/`. Это браузер с настоящим локальным API и тестовой БД, не фотографии живых обращений. Снимки и приватные данные не коммитятся.
