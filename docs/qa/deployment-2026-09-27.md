## Что исправлено

Точные `/actuator/health` и `/actuator/info` идут в Java. Остальной `/actuator` отвечает 404 `application/problem+json` с requestId, без SPA fallback. RELEASE_SHA обязателен в release Compose, без молчаливого unknown. Файл Семёна из `nginx.conf.zip` сверен с текущим конфигом; сохранены также ограничения методов, таймауты и no-store.

Cookies сессии и CSRF согласованы с iframe MAX: `SameSite=None; Secure` на HTTPS. Локальный HTTP runner явно использует Lax/false. CSRF и HMAC не отключались; небезопасное None/false запрещено при старте. Встраивание документа ограничено CSP: свой origin и официальные web.max.ru/max.ru.

## Настоящий MAX Web

Вход после исправления cookies прошёл с настоящим Bridge. Одноразовое приглашение погашено через UI, сервер выдал роль «Житель» только синтетического дома. В чате последовательно отправлены «новое обращение», синтетическое описание, два пункта в формате категория/место/проблема и «готово». Бот ответил «Обращение подтверждено, пунктов: 2». После обновления контейнеров ops_status показал 1 подтверждённое обращение, 0 черновиков, 0 pending/failed исходящих, 6 sent, 0 pending/parked входящих, миграцию V11. Это проверка сохранности и реального транспорта, без подмены данных входа публичного сервера.

После первого успешного входа обнаружен конфликт служебного `WebAppData` hash с React Router: показывалась страница 404. В `cefd541` Bridge читает данные первым, затем fragment заменяется корнем или допустимым start_param; явные маршруты сохраняются.

Чистый запуск `cefd541` открыл «Мои обращения», без ложной 404. Обращение №1 из бота содержит два отдельных пункта: освещение и дверь. Через Mini App автор выбрал для освещения «Не могу проверить» и отдельно подтвердил отправку. После сохранения у света «Автор пока не может проверить», у двери «Автор ещё не проверил», итог 0 из 2. История содержит создание, два изменения списка, подтверждение и одно наблюдение. После повторного запуска по `startapp=<caseId>` открылась та же карточка с этим состоянием.

Тёмная тема и крупный текст применились в настоящем окне MAX. При новом запуске в браузере Codex настройки вернулись к системной теме/обычному тексту без сообщения о недоступном storage. Причина сброса не установлена: это отдельная проверка в обычном браузере и MAX mobile, не заявлять сохранение предпочтений между запусками подтверждённым. Проверялись UI/DOM и нативный снимок окна, значения storage и signed initData не выгружались.

## Осталось проверить

 Полный сценарий с двумя реальными аккаунтами, MAX mobile, независимая приёмка Софии, holdout анализатора и нагрузка на сервере не засчитаны. Итоговая конкурсная версия не заморожена.

HTTPS работает, но внешняя маршрутизация TCP 80 не ведёт в этот nginx. Сертификат действует до 26.12.2026; автоматическое продление ещё не настроено. Подробная процедура и ограничения - [release](../release.md).
