# Дизайн Mini App: КОРЕНЬ внутри MAX

## Действующий дизайн - 27.09.2026

По прямому поручению пользователя интерфейс переработан для простой работы на телефоне и с крупным текстом. Задачи K-01/K-06. Источник текущего вида - `frontend/src/styles.css`, `components/`, `features/`; старые PNG и HTML в `design/` остаются историческим прототипом 22.09. Не возвращать прежнюю компоновку по этим картинкам. Матрица [screens](screens.md) сохраняет предметные состояния и соответствие API.

- Два постоянных раздела: обращения и доступ к дому. Выход находится на странице доступа; тема/текст/анимация - в отдельном доступном диалоге с кнопкой «Готово» и Escape.
- В списке одна основная кнопка создания. Переключатель дома нужен только при нескольких memberships. Строка обращения целиком открывает карточку, без вложенных интерактивных элементов.
- Создание: «Описание → Пункты → Проверка». Индикатор показывает этап формы, не статус ремонта. Сохранение черновика и явное подтверждение списка остаются разными командами.
- В карточке компактная квитанция, серверный прогресс и пункты. Сведения о работах и проверка автора визуально разделены. Нерешённые пункты первыми; исходный номер сохраняется. Отзыв/архив доступны в «Других действиях», причина и отдельное подтверждение обязательны.
- Исходник, история и состояние пункта в форме наблюдения раскрываются по запросу. История впервые запрашивается только после открытия; права, пагинация и invalidation остаются в Query/Java.
- На широком экране очередь - таблица, отчёт - две колонки. Все формы, ошибки и подтверждения используют общие компоненты. API, бизнес-команды, версии и повторы не заменены макетом.

Проверки и воспроизводимые снимки работающего React на синтетических fixtures/PostgreSQL: [редизайн 27.09](qa/redesign-2026-09-27.md). Автотесты не заменяют тестирование с пожилыми пользователями и screen reader на устройствах.

## Источник оформления и границы соответствия

[Официальный MAX UI](https://dev.max.ru/ui), [исходные цветовые токены](https://github.com/max-messenger/max-ui/blob/1df07bd7c740374cd40612c07654c3fade7c2e9f/src/styles/variables/appearance.scss), [типографика/общие переменные](https://github.com/max-messenger/max-ui/blob/1df07bd7c740374cd40612c07654c3fade7c2e9f/src/styles/variables/common.scss). Повторно проверены 27.09.2026 через Context7 и исходный Git commit `1df07bd7c740374cd40612c07654c3fade7c2e9f`. Официальная страница также ссылается на [Figma-файл](https://github.com/max-messenger/max-ui/blob/main/MAXUI-Figma.fig).

Это соответствие публичной UI-системе MAX, не заявление о согласовании с правообладателем полного маркетингового брендбука. Название и знак КОРЕНЬ сохраняются. Не выдавать продукт за официальный сервис MAX и не рисовать поддельную системную оболочку мессенджера. Синие оттенки - действия/навигация; зелёный только семантическое наблюдение, янтарный предупреждение, красный ошибка/необратимое решение. Статус всегда подписан текстом.

Проверенный source package MAX UI указывает exact peer React/ReactDOM 19.2.8, а проект имеет 19.3.0. Поэтому не добавлять библиотеку через force/legacy-peer-deps ради цвета. Простые semantic CSS tokens дают нужный вид без конфликта. Если позже выбирается опубликованная совместимая версия, проверить её реальные peers и accessibility, закрепить lock и только затем интегрировать компоненты.

## Компоненты и поведение

| Компонент | Источник данных | Обязательные состояния |
|---|---|---|
| AppShell/Header/Back | Текущий маршрут и разрешённый контекст | Вход, без доступа, back с несохранённым вводом, session expired |
| ContextSelector | `/me.memberships` | Один/несколько/нет контекстов; отзыв доступа; не выдаёт роль |
| Button/Field/Textarea | Контролируемая форма + server errors | Default, focus, hover, pressed, disabled, loading, invalid; label не placeholder |
| ItemCard/Progress | `items` и `progress` Java | Отдельно работа/наблюдение/admin; частичный итог, отзыв, архив |
| NextAction | `items[].nextAction` | Нет плана, актуальный, просроченное обновление, прошлый план в архиве |
| ReportEvidence/LinkChoice | Сохранённый report + валидная suggestion | Нет анализа, ошибка, точная цитата, ничего не выбрано, ручной выбор |
| ObservationForm | Автор + item/content/round/version | Три ответа, review, pending, stale, denied; не доступна диспетчеру за автора |
| Timeline | Авторизованная history, пагинация | Пусто, загрузка, ошибка, старые/новые раунды, причина admin |
| Error/Notice | problem+json code/requestId | 401/403/404/409/422/429/503, неизвестный исход, ручной путь |
| Theme/Text/Motion preferences | Только локальные предпочтения | System/light/dark, normal/large, уменьшение движения, storage unavailable |

Реальные role/UUID/даты/имена/номера не берутся из каталога. Человек видит «Обращение №…», сервер получает UUID. Слова «сохранено», «принято», «по вашему наблюдению» соответствуют разным событиям. Не показывать «отремонтировано системой» или проценты уверенности вместо проверяемой цитаты.

## Геометрия и адаптивность

Мобильный ориентир 390×844, узкий 320, tablet768×1024, широкий1440×1000. Это контрольные размеры, не требование поставить fixed width/height приложению. В mobile боковые поля16, на широком24; header min72/80, основной столбец max760. Нижние фиксированные панели отсутствуют: действия находятся в потоке, не перекрывают поля/клавиатуру. Учитываются safe-area и отступ после последнего элемента. Реальная высота зависит от viewport/клавиатуры. Не переносить `.export-full` в runtime.

На широком экране очередь становится таблицей, отчёт и выбор связей - двумя колонками. При нехватке места вертикальная компоновка без потери колонок/действий. Desktop sidebar в прототипе236px - ориентир; фиксированный export1440 не доказывает промежуточные размеры. Tablet-внешняя рамка и нарисованная клавиатура демонстрационные, не часть продукта.

## Взаимодействие и доступность

Focus outline3px/offset3; ошибки связаны с полем и доступны диктору; логичный heading hierarchy, `lang=ru`, semantic buttons/labels/fieldset. Dialog удерживает фокус, Escape/отмена возвращают его к триггеру. Без вложенных интерактивных элементов. Live region сообщает результат, не перебивает на каждом вводимом символе. Не скрывать существенную ошибку автоматическим toast.

Нажатие100ms, состояния150ms, появление180ms; easing cubic-bezier(.2,.7,.2,1). Появление экрана/диалога использует только transform на 3/6px: opacity текста всегда1, контраст не падает в переходе. Индикатор загрузки пульсирует только три секунды. CSS prefers-reduced-motion и явная настройка «Без анимации» отключают всё движение/переходы; выключение пользовательской настройки не отменяет системную. Никакой анимационной библиотеки. Движение не сигнал успешного server commit. Выключенная кнопка объясняет недостающий выбор; pending не позволяет двойное действие, сервер всё равно обеспечивает идемпотентность.

## MAX-интеграция

[Официальный Bridge](https://dev.max.ru/docs/webapps/bridge) подключается в Mini App, сырой `window.WebApp.initData` передаётся Java. `initDataUnsafe` не авторизует. Проверить реальные методы/события перед использованием, не переносить Telegram API по памяти. Клиент не перехватывает и не подменяет native MAX UI.

В localStorage только theme/large/reduceMotion; прежний формат theme/large совместим. При отказе storage вид применяется до закрытия, UI сообщает ограничение. Сохранение после reload проверено в локальном Chromium; прежний сброс в контейнере Codex остаётся отдельной проверкой настоящего MAX. System по умолчанию следует доступной системной теме; явный выбор light/dark перекрывает её. Если используется MaxUI provider, его colorScheme также должен совпасть с выбранным режимом. Переключение темы Mini App не меняет оформление чата MAX. Настройка уведомлений - отдельная серверная функция; исходный M05 честно направляет к настройкам чата и не рисует неработающий switch.

## Расхождения, устранённые спецификацией

1. D09/D10: выбранный пункт, не массовое архивирование обращения; текст/макеты обновлены.
2. Receipt/nextAction/displayNumber реализованы в S-01/S-03; allowedActions пока TARGET. Не показывать константы как серверные данные.
3. A08 - подтверждение содержания, A10 - приём сотрудником. Не один success-state.
4. Ввод ограничен 5000 code points для обращения/отчёта, location300, symptom/reason1000, максимум20 пунктов; frontend показывает те же ограничения, backend окончательно проверяет.
5. B04: display №124 не UUID/право. Startapp адресует сущность, Java проверяет доступ.
6. localStorage прототипа хранит учебный ввод; runtime переносит туда только preference, не персональный текст или полномочия.
7. S01/S02 - Should; отсутствие поиска не блокирует core и не означает отсутствие похожих случаев.
8. M06 support/privacy требует настоящих согласованных данных; M03 уже использует одноразовое серверное приглашение. Placeholder не считается готовностью.
