# Дизайн Mini App: КОРЕНЬ внутри MAX

Редакция 22.09.2026. Вход - приложенный пакет `koren-design`: 62 ID / 118 основных изображений. Его исходная структура сохранена, палитра и системная типографика адаптированы к MAX; D09/D10 приведены к архивированию пункта. Полный [каталог](../design/index.html), [редактируемый HTML](../design/KOREN_Design_Editable.html), [матрица экранов и API](screens.md). Всё это проектный прототип, не работающий продукт.

## Источник оформления и границы соответствия

[Официальный MAX UI](https://dev.max.ru/ui), [исходные цветовые токены](https://github.com/max-messenger/max-ui/blob/1df07bd7c740374cd40612c07654c3fade7c2e9f/src/styles/variables/appearance.scss), [типографика/общие переменные](https://github.com/max-messenger/max-ui/blob/1df07bd7c740374cd40612c07654c3fade7c2e9f/src/styles/variables/common.scss). Проверены 22.09.2026 через Context7 и исходный Git commit `1df07bd7c740374cd40612c07654c3fade7c2e9f`. Официальная страница также ссылается на [Figma-файл](https://github.com/max-messenger/max-ui/blob/main/MAXUI-Figma.fig).

Это соответствие публичной UI-системе MAX, не заявление о согласовании с правообладателем полного маркетингового брендбука. Название и знак КОРЕНЬ сохраняются. Не выдавать продукт за официальный сервис MAX и не рисовать поддельную системную оболочку мессенджера. Синие оттенки - действия/навигация; зелёный только семантическое наблюдение, янтарный предупреждение, красный ошибка/необратимое решение. Статус всегда подписан текстом.

Проверенный source package MAX UI указывает exact peer React/ReactDOM 19.2.8, а проект имеет 19.3.0. Поэтому не добавлять библиотеку через force/legacy-peer-deps ради цвета. Простые semantic CSS tokens дают нужный вид без конфликта. Если позже выбирается опубликованная совместимая версия, проверить её реальные peers и accessibility, закрепить lock и только затем интегрировать компоненты.

## Токены

Единственный редактируемый источник прототипа - `design/source/build_design.py`; генерирует [design-tokens.json](../design/design-tokens.json) и theme-vars.css. Runtime frontend перенимает согласованные значения, а не копию демонстрационной бизнес-логики. Изменение палитры проверяется в обоих местах до интеграции.

| Фон | #F5F7FA | #0F0F12 | MAX background-secondary / background-surface |
| Основная поверхность | #FFFFFF | #17181C | MAX background-primary |
| Вторичная поверхность | #EDEEF2 | #25262D | MAX surface / secondary |
| Основной текст | #060708 | #FFFFFF | MAX text-primary |
| Вторичный текст | #505359 | #C6C7CA | Непрозрачная адаптация для проверяемого контраста |
| Базовый синий MAX | #007AFF | #007AFF | MAX button-primary; хранится brand.primary |
| Рабочий акцент КОРНЯ | #0066CC | #479FFF | Светлый затемнён для AA; тёмный - MAX hover |
| Текст на акценте | #FFFFFF | #060708 | Контраст с соответствующей поверхностью |
| Дополнительный фирменный оттенок | #6813FF | #A473FF | MAX promo; не нужен как фон каждого экрана |

Белый обычный текст на #007AFF имеет расчётный контраст около 4.02:1. Поэтому у действий выбран #0066CC (около 5.57:1 на белом), а не слепое копирование цвета с недостаточным контрастом. Не объявлять каждую адаптацию точным официальным токеном. Полная семантическая палитра и проверенные пары - JSON/QA пакета.

Шрифт - системный sans-serif, без загрузки случайного Inter и без зависимости от сети. Базовый текст 18 px / line-height 1.48; подписи 15; заголовок 27; секция 20. «Крупный» ×1.25; проверка 200% отдельно ×2 от нормального, не растяжение screenshot. Масштабировать rem и контейнеры, не фиксировать высоту строк.

Сетка 4/8 px; интервалы 4,8,12,16,20,24,32,40,48. Карточка radius16/padding16, контрол radius12, border1. Основная кнопка min-height52, поле min-height56, интерактивная цель минимум44×44. Иконка24/stroke1.7; значимый icon-only control имеет accessible name. Status chip не кнопка и не обязан иметь 44px высоты.

## Компоненты и поведение

| Компонент | Источник данных | Обязательные состояния |
|---|---|---|
| AppShell/Header/Back | Текущий маршрут и разрешённый контекст | Вход, без доступа, back с несохранённым вводом, session expired |
| ContextSelector | `/me.memberships` | Один/несколько/нет контекстов; отзыв доступа; не выдаёт роль |
| Button/Field/Textarea | Контролируемая форма + server errors | Default, focus, hover, pressed, disabled, loading, invalid; label не placeholder |
| ItemCard/Progress | `items` и `progress` Java | Отдельно работа/наблюдение/admin; частичный итог, отзыв, архив |
| NextAction | `items[].nextAction` | Нет плана, актуальный, просроченное обновление, прошлый план в архиве |
| ReportEvidence/LinkChoice | Сохранённый report + валидная suggestion | Нет анализа, ошибка, точная цитата, ничего не выбрано, ручной выбор |
| ObservationForm | Автор + item/content/round/version | Три ответа, review, pending, stale, denied; не доступна диспетчеру за автора |
| Timeline | Авторизованная history, пагинация | Пусто, загрузка, ошибка, старые/новые раунды, причина admin |
| Error/Notice | problem+json code/requestId | 401/403/404/409/422/429/503, неизвестный исход, ручной путь |
| Theme/Text preferences | Только локальные предпочтения | System/light/dark, normal/large, storage unavailable |

Реальные role/UUID/даты/имена/номера не берутся из каталога. Человек видит «Обращение №…», сервер получает UUID. Слова «сохранено», «принято», «по вашему наблюдению» соответствуют разным событиям. Не показывать «отремонтировано системой» или проценты уверенности вместо проверяемой цитаты.

## Геометрия и адаптивность

Мобильный ориентир 390×844, узкий 320, tablet768×1024, широкий1440×1000. Это контрольные размеры, не требование поставить fixed width/height приложению. В mobile контент имеет боковые поля20 (16 на узком); header min64, основной столбец max640. Нижняя панель с safe-area и достаточным отступом последнему полю. Реальная высота зависит от viewport/клавиатуры. Не переносить `.export-full` в runtime.

На широком экране очередь становится таблицей, отчёт и выбор связей - двумя колонками. При нехватке места вертикальная компоновка без потери колонок/действий. Desktop sidebar в прототипе236px - ориентир; фиксированный export1440 не доказывает промежуточные размеры. Tablet-внешняя рамка и нарисованная клавиатура демонстрационные, не часть продукта.

## Взаимодействие и доступность

Focus outline3px/offset3; ошибки связаны с полем и доступны диктору; логичный heading hierarchy, `lang=ru`, semantic buttons/labels/fieldset. Dialog удерживает фокус, Escape/отмена возвращают его к триггеру. Без вложенных интерактивных элементов. Live region сообщает результат, не перебивает на каждом вводимом символе. Не скрывать существенную ошибку автоматическим toast.

Press90ms/state160ms/sheet200ms, easing cubic-bezier(.2,.7,.2,1); reduced-motion немедленно показывает итог. Движение не сигнал успешного server commit. Выключенная кнопка объясняет недостающий выбор; pending не позволяет двойное действие, сервер всё равно обеспечивает идемпотентность.

## MAX-интеграция

[Официальный Bridge](https://dev.max.ru/docs/webapps/bridge) подключается в Mini App, сырой `window.WebApp.initData` передаётся Java. `initDataUnsafe` не авторизует. Проверить реальные методы/события перед использованием, не переносить Telegram API по памяти. Клиент не перехватывает и не подменяет native MAX UI.

System по умолчанию следует доступной системной теме; явный выбор light/dark перекрывает её. Если используется MaxUI provider, его colorScheme также должен совпасть с выбранным режимом. Переключение темы Mini App не меняет оформление чата MAX. Настройка уведомлений - отдельная серверная функция; исходный M05 честно направляет к настройкам чата и не рисует неработающий switch.

## Расхождения, устранённые спецификацией

1. D09/D10: выбранный пункт, не массовое архивирование обращения; текст/макеты обновлены.
2. Receipt/nextAction/displayNumber/allowedActions отсутствуют в исходном Java record; добавлены как TARGET в API и S-01/S-03. До реализации не показывать константы как серверные данные.
3. A08 - подтверждение содержания, A10 - приём сотрудником. Не один success-state.
4. Ввод ограничен 5000 code points для обращения/отчёта, location300, symptom/reason1000, максимум20 пунктов; frontend показывает те же ограничения, backend окончательно проверяет.
5. B04: display №124 не UUID/право. Startapp адресует сущность, Java проверяет доступ.
6. localStorage прототипа хранит учебный ввод; runtime переносит туда только preference, не персональный текст или полномочия.
7. S01/S02 - Should; отсутствие поиска не блокирует core и не означает отсутствие похожих случаев.
8. M06 support/privacy и экран M03 требуют настоящих данных/серверной реализации; placeholder не считается готовностью.
