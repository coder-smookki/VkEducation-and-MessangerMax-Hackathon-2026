## Как проверять

С любой машины:

```
python3 scripts/stand_smoke.py --expect-sha <SHA сдачи>
```

На машине стенда, рядом с docker compose:

```
python3 scripts/ops_status.py
python3 scripts/db_backup.py backup --out-dir /srv/koren/backups
python3 scripts/db_backup.py verify /srv/koren/backups/<имя-созданного-дампа>.dump
```

Сначала задать COMPOSE_FILE/COMPOSE_PROJECT_NAME/COMPOSE_ENV_FILES по [release](release.md). Для сравнения backup/verify выбрать окно без записей: снимок сверяется с текущей БД.

`stand_smoke.py` проверяет HTTPS, health, SHA, закрытые actuator и demo, ошибку API в JSON и закрытые порты БД и Python. `ops_status.py` показывает версию миграции, застрявшие и отклонённые уведомления, отложенные входящие события и очередь анализа - только числа.

## Инцидент

Если что-то не работает, запись заводится сразу, а заполняется по мере выяснения:

- начало и конец (МСК), кто заметил;
- влияние: что не работало и для кого (проверяющий, автор, диспетчер, бот);
- причина, если известна, иначе «не установлена»;
- действие: перезапуск, восстановление (из какого дампа), повторный выпуск - и его SHA;
- проверка после: вывод `stand_smoke.py` (строка RESULT) и `ops_status.py`;
- что потеряно: данные между backup и восстановлением, если были.

Скрывать или «тихо» подменять сданную версию нельзя, даже если исправление маленькое.
