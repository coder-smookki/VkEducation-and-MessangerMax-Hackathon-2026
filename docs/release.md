# Выпуск и самостоятельная проверка

Целевой домен **https://hackathon.lumnex.ru/**. Этот документ - требования к S-07/K-07/Q-07, а не утверждение о настроенном сервере. Доступность реального домена/бота подтверждается отдельным протоколом.

## До развёртывания

1. Закрепить SHA и минимальный набор функций; Should выключен, если не прошёл приёмку.
2. Настроить DNS/TLS, static frontend, proxy `/api/v1` и отдельный `/max/webhook`. API не должен fallback в index.html. Убедиться, что main lumnex.ru не затрагивается.
3. PostgreSQL/Python/Kafka/Chroma только в private network. Секреты передать окружением/секрет-хранилищем; токен не в URL, JS, образе, source map, Git и логах.
4. Завершить проверенную сессию/CSRF/Membership, выдать тестовые роли контролируемо. Никаких userId/role overrides для облегчения демонстрации.
5. Проверить поддержку HTTPS Mini App и webhook в фактически выданном боте, права на запуск, реальное имя бота и открытие через MAX. Не восстанавливать токен из screenshot/истории в публичные файлы.
6. Заполнить реальные support/privacy контакты и правила хранения. Синтетический стенд явно подписан. Массовые уведомления и рассылка соседям отсутствуют.

## Сборка и данные

Существующий Compose - dev. Отдельный release profile создаётся и проверяется; стандартный release не должен грузить необязательные embeddings/индекс ради ручного пути. Не отключать реально заявленный ML незаметно. Lock-файлы обязательны, `npm --force`/`--legacy-peer-deps` не скрывают несовместимость зависимостей.

Чистая source-build измеряется в изолированной среде: SHA, ОС/CPU/RAM, сеть, подготовленные базовые Docker images, время полной команды вместе с зависимостями. Цель ≤5 минут из Blueprint проверяется этим способом. Не очищать общий Docker cache/volume команды ради проверки. Если цель не достигнута, записать факт и оптимизировать ненужные зависимости.

Seed запускается отдельным явным шагом и только для synthetic data. Обычный restart/upgrade не удаляет существующие обращения. V1/V2 не переписываются. До миграции непустой среды backup, после - контроль ключевых counts/связей. Restore проверяется в отдельную БД, не поверх рабочей без разрешения.

## Проверка другим участником

София открывает release из чистого checkout и следует только README. Затем реальными автором и диспетчером: создать свет+дверь в боте → подтвердить → открыть ту же карточку в Mini App → принять → задать шаг двери → сохранить отчёт о свете → явно связать → автор отмечает свет → остаётся дверь. Повторить с новым synthetic case, остановленным Python и старой callback-кнопкой. Зафиксировать UUID, версии, mode и факт доставки без чувствительного payload.

Для технического оператора нужен health, версия приложения, агрегированные queue/errors и requestId. Не открывать внутренние actuator details/public SQL для диагностики.

## Комплект сдачи

Согласованные исходники/архив, README запуска, API/данные/env без секретов, работающие ссылки, краткие материалы с действительными скриншотами и ограничениями, инструкция ролей и двухпунктового сценария. Всё относится к одному SHA. Закрытые credentials - только в предназначенный проверяющим канал. Самостоятельно отправлять сообщения организаторам без поручения нельзя.
