# Навигация по проекту

Документы самодостаточны: для начала работы не требуется искать предыдущий разговор или PDF на чужом компьютере. Указания в исходном отчёте являются проектными предложениями; приоритет имеют актуальный запрос команды и проверенные условия хакатона.

## Порядок чтения

1. [Текущее состояние](memory/PROJECT_STATE.md) - что реализовано, что ещё нет.
2. [Продукт](product.md) - задача, сценарий, границы MVP.
3. [Архитектура](architecture.md) и [правила](domain.md) - владельцы данных и инварианты.
4. [Контракты API](api.md), [пять контрактов обработки обращения](../contracts/README.md) и [план реализации по слоям](implementation.md) - DTO, подтверждение пунктов, уточнение только у автора, похожие обращения, транзакции и workers. Целевой API явно отделён от существующего.
5. [Общий план](plan.md) и [параллельная разработка](parallel-development.md), затем свой: [Кирилл](team/kirill.md), [Семён](team/semyon.md), [Никита](team/nikita.md).
6. [Сквозной пример](worked-example.md) - конкретные команды, версии и результат сценария «свет + дверь».
7. [Запуск](development.md), [сценарии приёмки](acceptance.md) и [фактические проверки](testing.md).

## Как поддерживать документацию

План хранит ожидаемый результат задачи; `PROJECT_STATE.md` - доказанный текущий результат; `DECISIONS.md` - причины архитектурных решений; `HANDOFF.md` - только передачу. Не размножать один журнал по папкам участников. При параллельной работе участник уточняет свой план, а общий статус/память обновляет Кирилл после интеграции результатов.

Для нейронки обязательный маршрут: состояние → инварианты → контракт → задача своего участника → реальные файлы → проверка → краткая передача. Предложенные имена новых файлов, endpoints и миграций не означают, что они существуют. Не отмечать соседний компонент готовым по тестовой фикстуре.

Статусы задач: `TODO`, `IN_PROGRESS`, `BLOCKED` с причиной, `DONE` со ссылкой на проверку. Исходное состояние всех задач хакатона - `TODO`: наличие каркаса не означает готовность соответствующей функции.
Время и даты записывать в Europe/Moscow. Не хранить токены MAX, реальные обращения и полные логи в памяти.
