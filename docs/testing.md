## Как проверять текущую задачу

Команды - [development.md](development.md). При правке документации достаточно проверить ссылки, контракты утверждений, владельцев, task IDs, manifest и `git diff --check`; не приписывать ей повтор всех runtime-тестов. При изменении поведения выполнить тест слоя и связанные QA-сценарии. Для SQL/идемпотентности использовать PostgreSQL. Для MAX нужна отдельная реальная сессия/доставка.

Дизайн-пакет имеет собственные QA-файлы. Они проверяют **локальный прототип**, а не auth/HTTP/БД/MAX. Состояние DONE в screens-manifest означает изображение. Проверки новой палитры/рендера фиксируются в `design/qa/qa-report.md`.

## Шаблон записи Софии

| Поле | Что записать |
|---|---|
| ID / дата / проверяющий | QA-E01, время МСК, имя |
| Версия | git SHA, frontend/backend image, Python mode |
| Среда | локально/стенд; ОС/браузер/MAX версия, размеры viewport |
| Данные | только synthetic IDs; дом/роли/начальные версии |
| Шаги | конкретные действия/HTTP без credentials |
| Ожидание / факт | пользовательский результат и проверенное состояние |
| Результат | PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE |
| Доказательство | тестовый отчёт/скрин/ссылка на CI конкретного SHA |
| Дефект | серьёзность, владелец, минимальный reproducer, повторная проверка |

Не заполнять PASS заранее. NOT_APPLICABLE разрешён только для выключенного Should, не отсутствующего Must. BLOCKED содержит зависимость и ближайшее действие. Журнал новых фактов помещать в этот документ или связанную небольшую проверочную таблицу, без копирования полного разговора/логов.

## Серьёзность

P0 - утечка секретов/чужих данных, потеря состояния, обход авторизации. P1 - не проходит основной путь, ложное закрытие/наблюдение, неработающий вход/бот/deployment, критическая недоступность. P2 - обход существует и не нарушает инварианты; причина/ограничение зафиксированы. Косметика без потери смысла - P3. Открытые P0/P1 блокируют релиз.

## Независимая оценка Python

Отдельно development и holdout, не добавлять тестовую фразу в правила после просмотра и называть результат независимым. Единица - пункт/отчёт, учитывать корреляцию пунктов одного обращения. Метрики: число примеров/пунктов, покрытие не-воздержанием, precision по меткам, ложноположительные связи, точность evidence, latency. При отсутствии предсказаний precision=null. Состав/версия набора и режима сохраняются без реальных обращений. Три смешанные конструкции - обязательная регрессия, не весь evaluation.
