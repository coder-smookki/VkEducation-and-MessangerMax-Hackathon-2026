## Какие правила уже исполняются

`ItemStateTest`: отчёт не равен наблюдению; частичное подтверждение; пустое обращение; другой автор; план вместо выполненной работы; старая версия/раунд; новый раунд сбрасывает наблюдение; самостоятельное восстановление; поздний отрицательный ответ; архив/отзыв; сохранение знаменателя.

`SuggestionValidatorTest`: пропущенные/повторные itemId, устаревший sourceRevision, выдуманная цитата, Unicode с emoji и недопустимое утверждение в STUB.

`PostgresSchemaTest`: реальная миграция, чужой автор наблюдения, межзаявочная связь отчёта, обязательная причина архива. Это не полная проверка всех будущих SQL-операций.

## Приёмка рабочего MVP во время хакатона

Подробные предусловия, действия и ожидаемые результаты: [15 сценариев A01-A15](acceptance.md). Общая последовательность с версиями: [worked-example.md](worked-example.md). Это план будущих проверок; существующие доменные/контрактные тесты подтверждают только указанную выше часть каркаса.

| Сценарий | Обязательный результат | Когда/кто |
|---|---|---|
| Создание при остановленном ML | Черновик сохранён; доступен ручной список | G1, S1/K2 |
| Подмена initData/роли/дома | Доступ отклонён до выполнения команды | G1, K1/S1 |
| Два жителя, два дома | Чужие карточка, история и результат повтора не раскрываются | G1/G3, S6 |
| Ответ только про свет | По двери сохраняется отсутствие сведений | G1, S2/K3 |
| Будущее время / другое место / противоречие | Нет автоматического подтверждения ремонта | G2, N3/S4 |
| Совместная правка с одной expectedCaseVersion | Одна запись проходит, другая получает 409 | G3, S6 |
| Callback предыдущего раунда | 409, актуальный пункт не изменён | G1/G3, S3/S6 |
| Повтор той же команды | Одно событие, один эффект, прежний результат после проверки прав | G3, S5/S6 |
| Тот же key, другое тело | 409; не подменить старый результат | G3, S6 |
| Новый отчёт после ответа автора | Старое наблюдение остаётся в истории и не подтверждает новый раунд | G1/G3, S3 |
| Падение после durable inbox, до обработки | Событие обработано после рестарта | G3, K5/S5 |
| Сбой MAX после outbox commit | Ограниченный повтор; доставка видна; нет потери состояния | G3, S5 |
| Отказ от уведомлений / «не могу проверить» | Нет автоматического успеха и циклического опроса | G3, S3/S5/K4 |
| Исправление draft и подтверждение состава | Новая редакция до confirm; после него обычная замена запрещена; старый контекст не применяется | G3, S1/S4 |
| Неподдержанный/длинный/опасный запрос | Сохранённый разрешённый ввод, ручной/аварийный маршрут; лимиты до обработки | G3, все |
| Чистый checkout на другой машине | Выполняются documented команды, без локальных секретных путей | G4, любой второй участник |

## Что пока не проверено

Рабочая MAX-аутентификация и отправка сообщений, реальный CRUD и API-гонки, durable workers, настоящая NLI, её качество и нагрузка, процесс УК, Android/iOS-клиенты MAX, публичный HTTPS-deployment и восстановление реальных данных из backup. Они не заявляются реализованными.

`ml/scripts/evaluate.py` сегодня запускает STUB на 7 учебных диалогах / 14 пунктах: coverage=0, precision=null. Это проверка инструмента оценки. Никакого вывода о качестве NLI или экономии времени из этих чисел не следует.

## Готовность коммита и выпуска

Перед коммитом: проверены затронутые компоненты, чистый `git diff --check`, в индексе нет секретов/сборок, планы и память соответствуют реальному коду. Коммит - один короткий русский заголовок, без тела и coauthor trailers.

Перед сдачей: зафиксированы версии приложения/модели/данных, пройдены критические сценарии, проверены реальные условия конкурса, материал демонстрирует именно эту сборку. Публикация и отправка от имени команды требуют актуального поручения.
