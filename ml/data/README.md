# Development-набор разметки

Синтетические русские тексты про ЖКХ (свет, входная дверь, уборка, другое). Личных данных нет. В `examples.jsonl` записи помечены `origin: "synthetic-development"`, в `regression.jsonl` - `origin: "synthetic-regression"`. Это данные проверки анализатора, они не являются исходными записями живого приложения и не импортируются в его БД. Цифры по ним не являются held-out оценкой качества. Сверено с файлами и evaluator 27.09.2026.

## Единица разметки

Один подтверждённый пункт (item) плюс полный текст ответа исполнителя (`reportText`). Каждая строка `examples.jsonl` — один диалог: запрос `CompareRequest` и ожидаемые метки по всем пунктам запроса.

## Поля диалога

- `id` — стабильный идентификатор записи.
- `origin` — происхождение; в текущих файлах `synthetic-development` или `synthetic-regression`, в соответствии с назначением набора.
- `author` — роль автора текста отчёта; сейчас везде `contractor` (исполнитель).
- `templateGroup` — группа шаблона. Перефразы и исправления опечаток одной истории — та же группа, а не новый независимый шаблон.
- `split` — `development`, `regression` или `holdout`, по файлу. Вся `templateGroup` целиком относится к одному split: нельзя разводить перефразы одной заготовки по train/dev/test.

## Поля item-меток (`expected`)

Два допустимых вида (оба валидны, формат расширен эволюционно):

- Старый: `"<itemId>": "RELATION"` — только метка. Существующие строки не изменены и остаются валидными.
- Новый: `"<itemId>": {"label": "RELATION", "evidence": [{"start", "end", "quote"}]}` — метка плюс допустимые gold evidence spans.

Правила для gold evidence:

- Координаты — строго Unicode code points исходного `reportText`, полуинтервал `[start, end)`. Python-индексация строк совпадает с этой моделью; emoji — один code point (в UTF-16 он занял бы две единицы, это ловушка для Java/JS-потребителей).
- `quote == reportText[start:end]` — точная цитата, без склейки несмежных фрагментов.
- Для `INSUFFICIENT_INFORMATION` evidence не задаётся (в ответе сервиса — `null`).

## Смысл меток

| Relation | Что утверждает текст | Что проверять человеку |
|---|---|---|
| REPORTED_DONE | Сообщается о выполненной работе по этому объекту/месту | Это отчёт, а не физическое подтверждение |
| PLANNED | Намерение/запланированное действие, а не уже выполненное | Будущее время и условия |
| SYMPTOM_PERSISTS | Прямо сказано, что симптом сохраняется | Нельзя потерять «но света нет» после слов о замене |
| INSUFFICIENT_INFORMATION | Достоверной интерпретации для пункта нет | Данных мало или анализ отказался; пункт остаётся видимым |
| UNRELATED | Есть фрагмент о другом объекте/месте | Отсутствие упоминания само по себе не даёт эту метку |
| CONFLICT | В тексте несовместимые утверждения по одному контексту | Это не автоматическое преобразование класса contradiction у NLI |

При сочетании «работу сделали, но симптом остался» используется SYMPTOM_PERSISTS. CONFLICT — только неразрешимое противоречие, а не два независимых факта.

## Спорные и синтетические случаи

- Спорные случаи помечаются явно полем `disputed: true` и комментарием `note`; их не удаляют ради роста показателя. В regression есть один такой пример: `mixed-one-clause` (свет у входной двери не является отчётом о самой двери). В development спорных записей нет.
- Все тексты вымышленные; метка `synthetic` обязательна через `origin`.

## Три набора и что каждый доказывает

- `examples.jsonl` — development. На нём строились правила; цифры по нему показывают, что правила работают на известных примерах, и не больше.
- `regression.jsonl` — обязательная регрессия QA-A08: смешанные субъекты в одной фразе («Лампу заменили, дверь заменим завтра», обратный порядок, «дверь всё ещё сломана» и тот же класс в других формах). Фразы известны заранее, поэтому успех там доказывает только, что класс ошибок закрыт. Вся группа — один `templateGroup`, потому что это вариации одной конструкции.
- `holdout.jsonl` — пишет тот, кто не видел правил (Q-06). Пока файла нет, и `scripts/evaluate.py` отдаёт по нему `null`: это «не предоставлено», а не 0 и не 100%. Добавлять в правила фразу из holdout после просмотра нельзя — после этого она перестаёт быть holdout.

Верхние `metrics` в результатах оценки — всегда development, чтобы их можно было сравнивать с прошлыми прогонами; по наборам отдельно — поле `splits`.
