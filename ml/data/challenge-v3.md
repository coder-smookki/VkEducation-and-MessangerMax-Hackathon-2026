# Независимый синтетический challenge RULES v3

Файл: `challenge-v3.jsonl`. Дата фиксации: 28.09.2026, Europe/Moscow.

Набор подготовлен отдельным агентом до запуска сравниваемых анализаторов. Агент не читал `rules_analyzer.py`, изменения разработчика RULES или тексты `examples.jsonl` / `regression.jsonl`. Для формата прочитаны контракт 05, его примеры, Pydantic schemas, `data/README.md`, код evaluator и только названия/типы полей одной существующей строки. Семантические требования задания были известны заранее.

Все тексты вымышлены. Это независимый от реализации синтетический challenge, **не человеческий holdout, не реальные обращения и не оценка качества на пользователях**. После просмотра ошибок разработчиком набор становится известным challenge/regression; повторные улучшения на нём не доказывают обобщение.

## Состав

64 отчёта, 97 пар item/report, 31 `templateGroup`; в одном запросе 1-3 пункта. Категории: LIGHTING 37, ENTRANCE_DOOR 31, CLEANING 25, OTHER 4. Все запросы удовлетворяют ограничению 1-20 items. Версии и раунды варьируются; itemId стабильны.

| Основная gold-метка | Пунктов |
|---|---:|
| REPORTED_DONE | 31 |
| PLANNED | 10 |
| SYMPTOM_PERSISTS | 14 |
| INSUFFICIENT_INFORMATION | 30 |
| UNRELATED | 8 |
| CONFLICT | 4 |

Покрытие смыслов: простые положительные случаи, смешанные объекты, отсутствие сведений о соседнем пункте, два пункта одной категории в разных местах, неоднозначный адрес, формы `2-м` / `2-го` / «во второй», границы чисел 2/12 и 1/10, локальная область отрицания/вопроса/условия/инструкции, отменённые старые цитаты, явные исправления, смена состояния во времени и неразрешённое противоречие. Unicode-примеры включают non-BMP emoji, variation selector, ZWJ, combining mark и переносы строк.

## Правила разметки и чтения

- REPORTED_DONE означает утверждение текста о работе, не установленный факт ремонта. Явный безусловный план - PLANNED.
- Выполненная работа с явно сохранившимся симптомом - SYMPTOM_PERSISTS. Одно отрицание ремонта без утверждения текущего симптома недостаточно для этой метки.
- Условие, вопрос, инструкция, опровергнутая старая цитата, отсутствие данных и неоднозначная привязка к одинаковым категориям - INSUFFICIENT_INFORMATION.
- Явно другое известное место - UNRELATED. Простое отсутствие упоминания пункта не даёт UNRELATED.
- CONFLICT применяется к неразрешённым несовместимым утверждениям об одном объекте и времени/событии. Исправление или «вчера работало, сегодня снова не работает» не являются таким конфликтом.
- `expected[itemId]` совместим с evaluator: `{label, evidence?}`. Для 67 содержательных gold-ответов указаны точные срезы исходника в Unicode code points; для отказов evidence отсутствует. Срезы задают подходящие цитаты, а не единственно допустимую длину ответа анализатора.
- `origin: synthetic-independent-challenge`, `split: challenge`. Набор намеренно не включён в стандартный `SPLIT_PATHS`: root запускает отдельное сравнение замороженных вариантов. Считать item/report единицей оценки; перефразы одной `templateGroup` не объявлять независимыми наблюдениями.

Две строки `challenge-v3-063` и `challenge-v3-064` содержат спорные «кажется» / «похоже». У них `disputed: true`, основная метка INSUFFICIENT_INFORMATION и дополнительная допустимая REPORTED_DONE в `acceptableAlternatives[itemId]`. Объяснения находятся в `annotationNotes`. Текущий evaluator альтернативы не использует. Рекомендуется показывать отдельно строгую оценку всех 97 пунктов, результат на 95 бесспорных пунктах и sensitivity с учётом альтернатив; не заменять основной результат более выгодным молча.

Сравнение должно одновременно показывать coverage, ошибки содержательных ответов и ложные REPORTED_DONE/PLANNED. Высокая precision при массовом отказе не является достаточным доказательством полезности.
