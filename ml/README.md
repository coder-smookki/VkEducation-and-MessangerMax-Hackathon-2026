# Анализ текстов КОРНЯ / ДомПульса

Состояние исходников на 28.09.2026: `rules-baseline-v3`, локальная реализация поверх `09bd804`. Этот результат ещё не опубликован на сервере. Python/FastAPI возвращает подсказку по тексту; Java владеет пользователями, правами, PostgreSQL и всеми продуктовыми командами. Ответ анализатора не подтверждает ремонт и не связывает отчёт автоматически. Диспетчер отдельно выбирает связи, автор отдельно сообщает наблюдение. [Контракты](../contracts/README.md), [план Семёна](../docs/team/semyon.md).

## Что работает и что остаётся расширением

| Возможность | Состояние в коде | Публикация |
|---|---|---|
| `POST /internal/v1/compare` | `stub` либо `rules`; RULES `rules-baseline-v3` возвращает метки и точные цитаты | В release-конфигурации выбран RULES; публикация v3 требует совместного обновления Java/Python/frontend. Java анализирует сохранённый отчёт через свою durable очередь; Mini App получает состояние и результат только от Java |
| `POST /internal/v1/extract-items` | Честный STUB: `NOT_ANALYZED`, `MODEL_NOT_CONFIGURED`, пустые proposals | Автоматическое разбиение в Mini App не подключено; работает ручной редактор |
| `POST /internal/v1/clarify-items` | Проверяет наличие category/location/symptom, вопросы адресуются только AUTHOR | Отдельный экран вопросов модели в Mini App не подключён |
| `POST /internal/v1/similar-cases` | Производный Chroma-индекс, разрешённые кандидаты, версии, отдельные пары пунктов | Поиск выключен: Kafka и UI поиска в release не включены; публикация продуктовых снимков в Kafka ещё не подключена к CRUD/outbox |
| `GET /healthz` | Фактические `mode`/`modelVersion` через тот же `active_mode`, что и compare; состояние включения vectorStore | Доступен внутри сети приложения, без публичного порта Python |

RULES не использует генеративный LLM, fine-tuning, RAG или закрытый датасет. Chroma используется только расширением поиска, а не разбором отчёта. При недоступности анализа Java/интерфейс оставляют ручную проверку; отсутствие подсказки не выдаётся за успешный анализ. Независимая оценка на holdout ещё не выполнена.

## Структура и ответственность

```text
app/
├── core/                  # settings
├── shared/                # производный Chroma-индекс
├── features/
│   ├── inference/         # compare, RULES, схемы ответа
│   ├── intake/            # extract, clarify, similar и их контракты
│   └── indexing/          # Kafka consumer подтверждённых снимков
└── di.py                  # Dishka composition root
```

Изменять существующий ответственный модуль; новые сервисы/слои не нужны ради структуры. У Python нет реляционной продуктовой БД, миграций Alembic, прав на статусы и выполнения команд из текста.

`CaseEventPublisher` в Java пока является отдельно подготовленным адаптером, а не доказательством отправки каждого CRUD-события. Consumer умеет повторно читать историю и защищать индекс от отката версии. При поиске Python сравнивает только переданные Java кандидаты, не расширяет доступ и не объединяет обращения. Java проверяет доступ и снимки до/после HTTP. Неполный, отключённый или устаревший индекс означает отказ анализа, а не отсутствие дублей. Условия включения, replay, пороги и failure semantics - [контракт04](../contracts/04-similar-cases.md).

## Конфигурация

Переменные `Settings` имеют префикс `KOREN_`; ниже значения по умолчанию для самостоятельного запуска, не утверждение о live-env:

```dotenv
KOREN_COMPARE_ANALYZER=stub
KOREN_CHROMA_PATH=./data/chroma
KOREN_CHROMA_COLLECTION=inference_documents
KOREN_CHROMA_ENABLED=true
KOREN_KAFKA_ENABLED=false
KOREN_KAFKA_BOOTSTRAP_SERVERS=localhost:9092
KOREN_KAFKA_TOPIC=koren.case-updates
KOREN_KAFKA_GROUP_ID=koren-ml-indexer
```

Для RULES явно задать `KOREN_COMPARE_ANALYZER=rules`. [compose.release.yaml](../compose.release.yaml) делает это для сервиса `ml` в профиле `analysis` и фиксирует Kafka `false`; backend должен иметь `ANALYSIS_ENABLED=true`. [compose.yaml](../compose.yaml) - отдельная локальная конфигурация с demo и default STUB, её не объединяют с release. Изолированный health `ok` не доказывает доставку Kafka, полноту индекса или качество подсказки.

## Запуск и проверки

Из `ml/`, Python 3.12 и зависимости из `uv.lock`:

```sh
make sync
KOREN_COMPARE_ANALYZER=rules make run
make check
make evaluate
```

`make check` выполняет format-check, Ruff, Pylint и pytest. `make format` изменяет исходники; `make openapi` обновляет машинный контракт и требует согласования потребителей. Команды проверены по [Makefile](Makefile); `make help` перечисляет отдельные цели. `make evaluate` пишет результаты в `results/`; это development/regression, не оценка новых обращений.

## Границы v3 и воспроизводимое сравнение

Повторный QA 28.09 исправил одинарное цитирование, потерю знака/суффикса/дроби номера места и привязку двери лифта к входной двери. Добавлены 36 регрессий; текущие проверки - 195 PASS + 1 Kafka SKIP. [Протокол и пределы](../docs/qa/local-playground-2026-09-28.md). Неподдержанные адреса дают отказ от подсказки, а не выдуманное выполнение работ; подтверждённые человеком связи не изменяются.

V3 выбирает пункт с учётом всего переданного списка. Если одно утверждение подходит нескольким пунктам одной категории без точного места, возвращает `INSUFFICIENT_INFORMATION`. Проверяет этаж/подъезд, в том числе `2-м`; не переносит неоднозначный адрес из соседнего предложения. Поддерживает ограниченный словарь утверждений о свете, входной двери и уборке. Категория `OTHER` не интерпретируется.

Условия, вопросы, цитаты, инструкции, неизвестные слова в области утверждения и неразрешённые отрицания означают отказ от интерпретации. Это сознательно консервативная граница: например, двоеточие или безобидное неизвестное предисловие тоже могут отключить подсказку. При отказе диспетчер сохраняет возможность прочитать отчёт и вручную связать его с пунктом. `REPORTED_DONE` значит только «в тексте заявлен результат», а не подтверждение ремонта.

Цитата является одним непрерывным срезом исходного текста; индексы - Unicode code points. Точный срез не доказывает правильность смысла. Полную гарантию на произвольный русский текст RULES не даёт.

```sh
uv run python -m scripts.compare_rules --dataset data/examples.jsonl --output results/compare-development.json
uv run python -m scripts.compare_rules --dataset data/challenge-v3.jsonl --output results/compare-challenge.json
```

Сравниваются неизменённый v2 из evaluation fixture, минимальная проверка условий/вопросов/цитат поверх v2 и production v3. V2 не импортируется приложением и не копируется в runtime Docker image. Инструмент фиксирует SHA исходников/датасета, coverage, числители и знаменатели точности, ошибки `REPORTED_DONE`/`PLANNED`, классы и точность срезов. Для спорной разметки strict, исключение спорных примеров и acceptable alternatives считаются отдельно.

Challenge содержит 64 синтетических отчёта / 97 пунктов / 31 группу, подготовленных другим агентом до открытия первой версии v3. Это **не независимый human holdout**. Первая слепая оценка v3 дала 18 правильных содержательных ответов из 19, включая один ложный `REPORTED_DONE` на инструкции перед двоеточием. После исправления общего класса и дополнительных регрессий повторная проверка дала 12/12 содержательных ответов, 0 ложных `REPORTED_DONE`, coverage 12,37%. V2 на том же наборе: 31/50, 17 ложных `REPORTED_DONE`; минимальная проверка: 29/39, 9 ложных `REPORTED_DONE`. Повторный результат является регрессией, а не второй слепой оценкой.

Низкая coverage - существенное ограничение: в большинстве сложных формулировок v3 воздерживается. Development даёт 10/29 содержательных ответов, точность 10/10; отсутствие human holdout остаётся `null`. Эти числа нельзя представлять как 100% качество продукта. Точные метрики, первая заморозка, цена воздержания и условия выпуска - [QA v3](../docs/qa/rules-v3-2026-09-28.md). Разметка - [challenge](data/challenge-v3.md), общий протокол - [data/README](data/README.md).

Локально проверены 159 Python-тестов, 1 тест внешней Kafka пропущен без брокера; Ruff/format и Pylint проходят. Это не утверждение о новом CI или опубликованном сервере. Полный пользовательский G2 и независимая человеческая разметка остаются отдельной приёмкой Софии.
